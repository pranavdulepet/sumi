## Original notebook review

The following records describe the earlier notebook build and its test conditions. Current distribution and conversation behavior are documented above.

### The original product decision

Keep one question at the center of the experience. Can Sumi anticipate a choice well enough to save you work, while leaving the decision yours? On the Desk, a sealed guess commits Sumi to an answer before you decide. The Mirror counts its misses. On the Scroll, you own the sentence that other agents may use. The Seal makes sharing and delegation separate permissions.

## Changes made during review

| PRD question | Implemented decision | Reason |
| --- | --- | --- |
| Can the same holdout drive weekly tuning and demonstrate improvement? | Assign whole conversations to training, tuning or permanent evaluation. Exclude identical training and tuning pairs from the blind sample. Store both guesses before opening the observed reply. | Tuning directly against the displayed test rewards memorization. |
| What happens with very little history? | Show the actual denominator, offer ten choices, and keep guesses explicitly unscored until there is an observation. Start with up to twelve eligible examples and evaluate up to 200 in idle readings. | Two real observations tell the user more than an invented percentage. |
| How much of a transcript must be reread? | Start with recently modified files. Resume JSONL reads at a byte boundary with an encrypted, audited conversation context and a file-change check. | An assistant turn can arrive before the user's turn. A partial line can be completed later. |
| Who decides what Sumi may infer and share? | Require explicit source selection, show proposals with evidence, and default agents to scoped read access. Free-form advisory guesses carry no numerical confidence without calibration. | A strong-sounding model answer is insufficient evidence for acting on someone's behalf. |
| What does forgetting cover? | Remove source observations, embeddings, linked guesses and proposals, and rebuild Sumi-managed history. Keep explicit user-authored corrections. Stop before changing a repository with additional branches or remotes. | Old commits and derived logs can otherwise retain a deleted belief. Copies made independently by the user or an external agent are outside the notebook's control. |
| How does an agent earn permission to answer? | Accumulate predictions before the user answers. Use only explicitly enabled low-stakes formats, a per-agent threshold and at least twenty reviewed shadow predictions. Other questions go to the user. | Historical agreement is measurable. The person owns irreversible actions. |
| What does free testing mean? | Use installed local weights and fabricated records in temporary notebooks. Record real local grades. Cloud request budgets default to zero. | No personal archive or metered account is needed to verify the mechanics. |

## Outstanding evidence and scope

- The PRD defines acceptance as two weeks of daily real use, an improving Mirror score, and screens that need no explanation. Synthetic records and short runs cannot establish these. Track the number of guesses and the cold baseline alongside the personal score.
- Live hosted sign-ins and metered requests have not been exercised here. Installed local inference is the tested route. The app offers optional hosted idle reflection and grading. Jev can also predict the ten built-in setup choices with a separately enabled permission and record the selected option’s probability. With separate consent, overnight blind prediction can use a hosted model and fall back to the local model. In the subscription review build, choosing ChatGPT explicitly uses the verified plan for model-generated writing suggestions, predictions, reflection and grading. Existing local notebooks keep their selection. The plan transport is tested against a loopback server, with a signed-in account test still outstanding. Weekly catalogue signature verification and rollback checks are implemented. This local build uses the included catalogue because it has no public update host.
- First reading checks reply dates inside ChatGPT and Claude exports. It uses the last 90 days for a new import and defers older and undated replies. A recent Claude Code or Codex session starts with up to 800 lines near the end of the file. Idle reading resumes at the contiguous file cursor, including replies that crossed the preview boundary. Notes use file modification dates and produce adjacent-paragraph examples. The Messages adapter covers the plain-text column. Attachment-only and attributed-body-only messages are skipped.
- The existing harness has weekly validation for prompt and retrieval width and adjusts the repetition threshold from the share of displayed suggestions accepted with Tab. The complete month-long calibration, ghost acceptance, interruption, energy and latency targets require representative use. The packaged app did not finish opening the isolated energy-test notebook while the Mac was locked, so whole-app idle CPU, memory and battery impact are unmeasured. A miss can carry an exception or a replacement attached to a rule the prediction used. The Mirror checks recent live and incoming misses against the sentence used for the guess. It looks for possible exceptions on at least three distinct days across fourteen days, with one in the past fortnight, over a six-week window. Classification and a separate compatibility check use the installed local model. The user can inspect the dated observations, keep the belief, add an exception, or replace the sentence. Permanent held-out examples stay out of this review. The tests include a timing error that still agrees with the belief. Accuracy on naturally evolving preferences remains unmeasured.
- The distributable is Apple Silicon only. The public GitHub release is ad-hoc signed. Apple Developer ID signing and notarization remain outstanding. The website is available locally. No paid provider or signing account was used.
